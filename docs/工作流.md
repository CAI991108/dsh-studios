# 可复用工作流：从一句话到交付包

> 照 `omarchy-NTE` 这支片子抽象出来的。八步，每步都有明确产出和完成标准。
> 适用：1–3 分钟的解说型产品片 / 项目宣传片。**不适用**：15 秒纯梗片、纯实拍 Vlog。

---

## 0 · 立项（半小时）

| 项 | 产出 |
|---|---|
| 一句话主张 | 「别人 ricing 桌面，我 ricing 了 AI」这种能当封面字的句子 |
| 时长与规格 | 例：123 秒 / 1920×1080 / 30fps / 16:9 + 竖屏短版 |
| 交付对象 | 只发平台？还是也要给对方工程？ |

**完成标准**：主张句能直接当标题，不用再解释。

---

## 1 · 剧本（一页）

一个 JSON 或表格，每拍一条：

```json
{"id":"hook","text":"所有人，感受。这 Omarchy 是什么新时代赛博嘉豪。","caption":"所有人 感受，这 Omarchy 是什么新时代赛博嘉豪"}
```

- `text` 是念出来的，`caption` 是屏幕上的（可以不一样：去掉语气词、改标点）。
- 拍数控制在 12–18。超过 18 拍，2 分钟内讲不完。

**完成标准**：每拍都念一遍，掐表——总时长决定片子长度，不是反过来。

---

## 2 · 时间轴（唯一真相）

`film/timing.json`：

```json
{ "fps": 30, "total": 3705,
  "shots": [
    { "id":"hook", "from":0, "duration":135, "voiceFrom":12, "voiceDuration":87,
      "src":"audio/voice-hook.mp3" }
  ] }
```

- `from` 与 `duration` 用**帧**，不用秒——避免累积误差。
- `voiceFrom` 是旁白在镜头内的入点（留 0.4 秒呼吸），`voiceDuration` 是这条旁白多长。
- 画面、字幕、音效、旁白全部从这棵树派生。

**完成标准**：改任何一拍的 `duration`，全片自动重排且不打架。

---

## 3 · 素材（最花时间）

按来源分三类，全部落到 `public/`：

| 类型 | 做法 | 坑 |
|---|---|---|
| 录屏 | 4K/60 采集，慢动作用真慢放（改动画速度，不是重定时） | 分辨率不够时放大发软；圆角/光标/通知要清 |
| 字卡 | 代码画（标题、数字、菜单卡），别用设计软件导出图片 | 字卡一多，风格不统一就散 |
| 借素材 | 从别的片子里抠镜头 | **注意烧进去的字**——会和自己的字幕叠两层 |

**完成标准**：`public/` 里的东西换台机器能直接跑。

---

## 4 · 声音（三层，分开做）

1. **旁白**：一拍拍，每拍一个文件，文件名 = 拍 id（`voice-hook.mp3`）。念错就重念一条，不影响别人。
2. **音效**：签名音效集合（whoosh / hit / typewriter / switch / vinyl），全片复用同一套。
3. **配乐**：一条完整曲子 + 一条无 BGM 版本（平台审核、二次剪辑都要）。

**完成标准**：关掉 BGM，片子还立得住；关掉旁白，音效还听得懂。

---

## 5 · 字幕

- 从剧本的 `caption` 派生，不手打第二遍。
- 中文硬字幕（ASS，描边），英文软字幕（SRT）。
- 一行 ≤ 18 字，停留 ≥ 1.2 秒。

**完成标准**：随便抽 5 条，时间码都对得上画面。

---

## 6 · 渲染

- Remotion `npm run build` → 出 1080p30（或 4K60）。
- 同时出「无 BGM 版」。
- 成片、封面、字幕一起进 `original/`。

**完成标准**：解码完整（`-v error -i out.mp4 -f null -` 无报错）。

---

## 7 · 验收（照抄这张表）

- [ ] 独立解压到**带中文和空格的新目录**再跑（不要在原目录验）
- [ ] `npm ci` 能装完，不用原来的 `node_modules`
- [ ] typecheck / build 通过
- [ ] 编辑器能载入全部镜头、字幕、音轨（数字对得上）
- [ ] 改一条字 → 预览可见 → 导出 JSON 里确实改了
- [ ] 导出片段 → 抽帧确认改字进了编码
- [ ] 出 sha256 + 比特流哈希，多版本视频流一致
- [ ] 扫凭据（key/token）、扫绝对路径（`C:\Users\...`）
- [ ] 隐私逐帧检查（余额、邮箱、通知、真实姓名）
- [ ] 数据口径复核（1KB / 30KB / 22×32 / 192 / 7 / 0 这类数字）
- [ ] 写「无法验证项」——诚实列表

---

## 8 · 交付包

```
original/    成片 + 封面 + 中英字幕 + 发布文案
film/        Remotion 源码 + timing.json
public/      全部素材
src/         编辑台
docs/        制作规格 / 独立复核 / 素材来源 / 验收记录 / QA JSON
licenses/    授权原文
README.md    怎么跑、怎么改、谁负责哪块
```

**完成标准**：一个不懂 Remotion 的人，双击启动器就能改字并导出。

---

## 复用清单（下一支片子开工时）

1. 复制 `film/`、`src/`、`scripts/`、`启动编辑台.cmd` 作为骨架。
2. 清空 `public/` 和 `original/`，保留字体。
3. 重写 `timing.json` 的 `shots`，`fps` 和 `total` 按新片算。
4. 新建 `docs/production-spec.md`，第一节就写「授权与范围」。
5. 剧本先定，**时间轴跟着剧本走**，不要先剪再配词。
6. 声音三层分开做，旁白按拍切文件。
7. 验收表照抄，一条不省。
8. 交付前跑一遍「换台机器能不能跑」。

---

## 一条反向经验

这套流程重。片子短于 30 秒、或者只有 3–5 个镜头时，直接 ffmpeg 拼更快——别为了流程而流程。
判断标准：**要改第二遍吗？** 要改，就上这套；一次成型，就别上。
