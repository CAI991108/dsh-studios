# 第一次实战：omarchy-NTE

这套生产线是从一支真片子里抽出来的，不是先有方法再找例子。

## 片子

`omarchy-NTE · 生产力，稍后再说`，2 分 03 秒，1080p30，中文旁白 + 中英字幕。

内容是 Arch + Hyprland 的桌面美化，配一套 DeepSeek Harness（「蓝色大肥鱼」）的像素皮肤。17 个镜头、66 条字幕、5 条轨道、127 个片段。

## 它暴露的那个洞

做这支片子时，前后两半其实都已经有了：

- **前半段**是一叠文档：定稿清单、分幕总览、分镜脚本、拍摄提示卡、制作手册、词表、3 条 ADR，还有一个能在浏览器里播的 animatic。
- **后半段**是一台机器：Remotion 影片源码、`timing.json` 单一时间轴、浏览器编辑台、启动器、渲染接口。

但两半是手工接的。接缝只有一个文件——`film/workbench.ts`，8 行，把这支片子的镜头一个个映射成编辑台要的格式。**每来一支新片，这 8 行重写一遍。**

而那份「可复用工作流」的复用清单里，只写了「重写 timing.json 的 shots」，偏偏没写这一步。缺口正好落在最需要它的地方。

## 这一版做了什么

把这 8 行变成一条命令：定稿 → `npm run derive` → 时间轴 → 清单。`Film.tsx` 和 `workbench.ts` 从此是通用代码，片子之间只在三个地方不同：`film.config.json`（长相）、`timing.json`（时间）、`scenes/`（镜头类型）。

同时补了原流程缺的两步：**定稿门**（状态机从 Markdown 表变成 `status` 字段，`已定` 只能由人推）和**装配**（加镜头只动注册表）。

## 为什么值得

判据只有一条：**会不会改第二遍**。

会改的片子，痛的不是第一次剪，是第二十次改：画面改了字幕没跟上、字幕改了时间没重排、新加一个镜头要动四处。单一真相让改一处就对；注册表让加镜头不动装配；`npm run qa` 让改完还敢发。
