# 门

三道门，每道都有「能自动判」的一半和「只能人判」的一半。自动的那半跑 `npm run qa`；人的那半在下面，照着打勾。

## 一 · 定稿门

`定稿.json` 里每一拍的 `status`，是一个只进不退的状态机：

| 状态 | 意思 | 谁推 |
|---|---|---|
| `待定` | 还没有方案 | 人 |
| `待选` | 有几稿在等挑 | 人 |
| `提议` | agent 写了，等点头 | agent 写，人推 |
| `待改` | 规则变了，内容要跟着改 | agent 标，人确认 |
| `已定` | 人确认过 | 人 |

规矩只有一条：**`已定` 只能由人推上去。** agent 可以写 `提议`，可以做 `待改`，可以在 `提议` 上迭代十稿；把 `提议` 改成 `已定` 的那一下，是人点头的。

一个 `已定` 的拍，改它的理由必须是**规则变了**，不是「感觉不对」。所以每次退回，顺手把规则写进 `定稿.json` 的 `notes` 或片子的 `docs/` 里——下次不会又改回去。

`待定` 的拍可以留在 `定稿.json` 里，它不许进入渲染。`npm run qa` 会逐条点出来；草稿阶段用 `npm run qa -- --draft` 放行（`--` 前面那个不能省，否则 npm 会把参数吃掉）。

## 二 · 验收门（自动那半）

`npm run qa` 查这些：

- 定稿门：每条 `status` 是 `已定`；`frames` 之和 = `timing.total`
- 每拍的 `scene` 在 `SCENES` 里注册过
- 时间轴：`from` 首尾相接、无空隙无重叠、末尾 = `total`
- 字幕：不越界、不空、重叠会提醒
- 素材：`voice` / `sfx.src` / `music.src` 指向的文件真在 `public/` 里
- 泄漏：扫 `定稿.json`、`timing.json`、`film.config.json`、`workbench.ts` 里的凭据模式与绝对本机路径
- 产物：`exports/*.mp4` 存在且不是几 KB 的坏片，给 sha256
- 代码编得过：`tsc --noEmit`，覆盖面是 `src` **和** `film`（没装依赖时降级为提醒）

最后一条是最容易漏的。只检查 `src` 的 `tsconfig` 会让 `tsc` 对着半套代码发绿，而 `film/` 里的错要等到渲染才炸——门要**覆盖得到**，光严格没用。

## 三 · 验收门（人那半）

自动门绿了只是一半。这一半每次都要过，一条不省：

- [ ] 在**另一个目录、带中文和空格**解压一份，`npm install` 能装完，不用原地 `node_modules`
- [ ] `npm run typecheck` / `npm run build` 通过
- [ ] 编辑台能载入全部镜头、字幕、音轨，数字对得上定稿
- [ ] 改一条字 → 预览可见 → 导出的 JSON 里确实改了
- [ ] 导出片段 → 抽帧确认改字进了编码画面
- [ ] 逐帧隐私检查：余额、邮箱、通知、真实姓名、API key
- [ ] 混音：关掉 BGM 片子立得住；关掉旁白音效听得懂
- [ ] 版权：字体、音效、配乐、角色形象，逐条对 `docs/sources.md`
- [ ] 数据口径复核：片子里说的每个数字，回到源头核一遍
- [ ] 写「无法验证项」——诚实列表比假装全验过可信得多

## 交付包

```
定稿.json      片子的话与状态
film/          Film.tsx（通用）· timing.json（唯一时间轴）· workbench.ts（通用清单）· scenes/ · assets
src/           编辑台
public/        全部素材
docs/sources.md  素材台账
exports/       成片 · 无配乐版 · 封面
README.md      怎么跑、改哪里
```

## 反向经验

这套流程重。片子短于 30 秒、或只有 3–5 个镜头，直接 ffmpeg 拼更快——别为了流程而流程。判据：**要改第二遍吗？**

要改，就上这套，因为它的全部价值都在第二遍：单一真相让改一处就对，注册表让加镜头不动装配，验收门让改完还敢发。
